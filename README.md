# Дежурства для Bitrix24

Рабочий MVP для двух типов графика: офис по пятницам и поддержка клиентов в выходные/праздники. Учёт отсутствий ведётся во внутренних часах: суббота поддержки списывает 2 часа, оба выходных — 4 часа. Офисное дежурство не меняет баланс.

## Локальный запуск

Требуется Node.js 22.5+ (используется встроенный SQLite).

```bash
cd outputs/duty-app
npm start
```

Откройте `http://localhost:3000`. В демо-режиме нажмите «Режим администратора», чтобы проверить назначения и отсутствие. Данные лежат в `duty.sqlite` рядом с сервером.

## Развёртывание на сервере

В проект добавлены `Dockerfile`, `compose.yaml` и Caddy: он сам получает и продлевает HTTPS-сертификат. Подробная инструкция по домену, серверу и Bitrix24 дана в файле `DEPLOY.md`. Если используете Render, Caddy и `compose.yaml` не нужны: Render сам даёт HTTPS, а для SQLite следует подключить Persistent Disk к `/app/data`.

## Подключение novoi.bitrix24.kz

1. Разместите приложение на HTTPS-домене.
2. В разделе для разработчиков Bitrix24 создайте локальное приложение и укажите обработчик `https://<ваш-домен>/install`, стартовую страницу `https://<ваш-домен>/`.
3. Запросите права `user` и `im`. Сотрудники и фотографии будут загружаться через `user.get`; напоминания отправляются через `im.notify.personal.add` или `im.message.add`.
4. Задайте `ADMIN_TOKEN` в окружении сервера. В рабочей версии проверка администратора должна опираться на подписанную OAuth-сессию Bitrix24; демо-переключатель предназначен только для локальной проверки.

Для напоминания за 3 часа нужен планировщик на хостинге: каждые 5 минут он ищет дежурства, начинающиеся примерно через 180 минут, и отправляет уведомление с уникальным тегом, чтобы избежать дублей.
