# Развёртывание «Дежурств»

## 1. Что купить/подготовить

Нужны домен и небольшой VPS с Ubuntu 24.04 LTS, публичным IPv4 и открытыми портами 80/443. Достаточно 1 vCPU, 1–2 GB RAM и 20 GB диска. Это сервер, на котором будут храниться график, баланс и токены Bitrix24.

Пример домена: `duty.novoi.kz`. В панели регистратора домена создайте DNS-запись типа `A`: имя `duty`, значение — публичный IPv4 вашего VPS. Дождитесь распространения DNS.

## 2. Подготовить VPS

Подключитесь по SSH как пользователь с правами `sudo` и выполните:

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y docker.io docker-compose-plugin openssl
sudo usermod -aG docker $USER
exit
```

Подключитесь к серверу снова, затем скопируйте папку `duty-app` на сервер: например, в `/opt/duty-app`. Не копируйте файл базы с рабочего компьютера, если начинаете с чистого графика.

```bash
cd /opt/duty-app
cp .env.example .env
nano .env
```

В `.env` задайте ваш домен и замените `ADMIN_TOKEN` на результат команды `openssl rand -hex 32`. Никому не передавайте это значение.

## 3. Запустить и проверить HTTPS

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f caddy
```

После выпуска сертификата откройте `https://duty.novoi.kz`. Если сертификат не выпускается, сначала проверьте DNS, а затем разрешите входящие TCP 80 и TCP/UDP 443 в firewall и панели VPS.

Для обновления приложения в будущем:

```bash
cd /opt/duty-app
docker compose up -d --build
```

База находится в Docker-томе `duty_data`. Раз в день снимайте резервную копию:

```bash
docker run --rm -v duty-app_duty_data:/data -v $PWD:/backup alpine sh -c 'cp /data/duty.sqlite /backup/duty-backup.sqlite'
```

## 4. Добавить локальное приложение в Bitrix24

Откройте в портале `novoi.bitrix24.kz`: **Приложения → Ресурсы разработчика → Другое → Локальное приложение**. Локальное приложение работает только внутри этого портала.

Заполните карточку:

| Поле | Значение |
|---|---|
| Название | Дежурства |
| Путь к приложению | `https://duty.novoi.kz/` |
| Путь для первоначальной установки / обработчик установки | `https://duty.novoi.kz/install` |
| Пункт меню | Дежурства |
| Права | `user`, `im` и базовые права приложения |

Не выбирайте «Использует только API»: приложению нужен пункт меню и интерфейс внутри Bitrix24. После сохранения Bitrix24 вызовет `/install` и передаст OAuth-данные на сервер. Сервер хранит их в собственной базе — не в браузере.

## 5. Напоминания в чат Bitrix24

В приложении заложены два правила: офисное дежурство — пятница 17:00–18:00, напоминание в 14:00; поддержка — суббота 09:00–18:00, напоминание в 06:00. Для автоматической отправки добавьте права `im` локальному приложению и создайте входящий вебхук Bitrix24 с правом **Чат и уведомления**.

В Render → **Environment** добавьте:

| Переменная | Значение |
|---|---|
| `BITRIX_IM_WEBHOOK` | базовый URL вебхука до `/im.notify.json` |

После перезапуска сервис сам проверяет расписание каждую минуту по времени Алматы: в пятницу около 14:00 и в субботу около 06:00. Поэтому Web Service должен оставаться включённым в это время; на тарифе со «сном» автоматические напоминания могут быть пропущены.

В самом приложении администратор может проверить доставку кнопкой «Отправить напоминание сейчас» в разделе «Мой баланс и обмены». Система не посылает один и тот же автоматический сигнал дважды.

## 6. До реального запуска

Перед тем как открыть приложение всем сотрудникам, следует завершить три настройки в исходном коде: загрузка сотрудников/аватаров через `user.get`, обновление OAuth-токена через `refresh_token`, и планировщик напоминаний за 3 часа через `im.notify.personal.add`. Эти данные привязаны к вашему созданному приложению и порталу, поэтому их подключают после шага 4.

После создания локального приложения передайте только его `client_id` (не секретный ключ) и подтвердите домен размещения. Секрет приложения остаётся в переменных окружения VPS, а не в переписке.
