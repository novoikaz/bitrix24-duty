# Статичное локальное приложение Битрикс24

Эта версия приложения работает без Render и без SQLite:

- файлы интерфейса загружаются ZIP-архивом в Битрикс24;
- сотрудники и аватарки читаются из пользователей портала;
- дежурства, отсутствия, бонусы, обмены и история хранятся в универсальном списке `duty_roster_data_v2`;
- уведомления отправляются через `im.notify.personal.add`;
- существующий бизнес-процесс графика отсутствий вызывается через список с ID `128`.

## Собрать ZIP

```bash
npm run build:static
```

Готовый файл: `dist/bitrix24-duty-static.zip`.

## Создать приложение в Битрикс24

1. Откройте **Приложения → Разработчикам → Другое → Локальное приложение**.
2. Выберите тип **Статичное**.
3. Загрузите `bitrix24-duty-static.zip`.
4. Название пункта меню: **Дежурства**.
5. Добавьте права:
   - Пользователи (`user`);
   - Списки (`lists`);
   - Чат и уведомления (`im`);
   - Календарь (`calendar`);
   - Бизнес-процессы (`bizproc`).
6. Сохраните и откройте приложение от имени администратора. Страница установки автоматически создаст универсальный список и поля.

## Перенести рабочие данные

1. В прежней версии на Render откройте **Настройки → Экспорт для переноса в Битрикс24**.
2. Нажмите **Скачать данные** и сохраните JSON-файл.
3. Откройте новую статичную версию.
4. Перейдите в **Настройки → Перенос данных из прежней версии**.
5. Выберите JSON-файл и нажмите **Импортировать данные**.
6. Сравните:
   - количество дежурств;
   - количество отсутствий;
   - баланс каждого сотрудника;
   - заявки на обмен;
   - последние записи истории.

Render следует отключать только после этой проверки.

## Автоматические напоминания

Статичное приложение не выполняет код в фоне. Напоминания перед дежурством нужно настроить бизнес-процессом универсального списка:

- офис: ожидать до пятницы, затем отправить уведомление назначенному сотруднику;
- поддержка: ожидать до субботы, затем отправить уведомление назначенному сотруднику.

Ручные уведомления и уведомления по обменам отправляются приложением сразу.

## Права доступа

Универсальный список создаётся с правом изменения для сотрудников, потому что сотрудникам нужно подтверждать собственное офисное дежурство и отвечать на обмены. Интерфейс проверяет роли редактора и администратора, однако для строгого разграничения на уровне данных потребуется вынести действия сотрудников в отдельный список и обрабатывать их бизнес-процессом.
